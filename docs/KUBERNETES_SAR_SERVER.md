# Opt-in authenticated persistent SAR listener

The binary has an additive default-off `--kubernetes-authorization-config <file>` listener, using the SAME native Authority/Policy/CompiledPolicy/View and existing grants. It does not translate a Kubernetes API assertion into Hop Human/Service/Workload authentication or mint a receipt. Existing management/native/gRPC listeners, defaults and network/guard semantics remain unchanged. The core mapping still only authorizes explicit `kubernetes_api` services at AAL0; no fake IP or Sum evidence is supplied.

## Immutable configuration and preflight

Private JSON has exactly: `version:1`, `listen` socket address, fixed canonical `cluster`, exact HTTP `authority`, `certificate`, `key`, `client_ca` file references, `client_sha256` array of1..16 distinct lowercase64hex SHA256 leaf-DER fingerprints, and `caller_token_env` reference. Config capped64KiB, TLS files bounded1MiB by shared helper; token32..4096 graphic bytes, distinct from administrator and decision credentials. No raw token in config/Debug/status/errors. The operator supplies ordinary admin/decision environment credentials as well as this separate SAR reference. `--check-kubernetes-authorization` requires the config flag, validates caller/TLS/clock without opening database/listeners and prints only a fixed success line. Unknown/missing/invalid configuration refuses startup. Inspector/observe-only modes cannot activate this listener.

Mandatory verified mTLS plus exact fingerprint allowlist establishes API-server transport identity; a CA-valid unrelated leaf is insufficient. EVERY request also requires exactly one Bearer credential. One immutable listener fixes one cluster; no header/IP/Host/body/UID/extra selects it. Supervised listener restart is required for caller pin/token/TLS changes and retires all its old connections. No ongoing remote-directory/certificate-revocation lookup is claimed. Tickets/session storage/early data are disabled; TCP/TLS connections themselves remain reusable. Linux BOOTTIME is required only for this opt-in listener; unsupported clock fails its preflight/startup, with no weaker fallback or change to absent-config legacy behavior.

## Restricted persistent HTTP/1 transport

Verified HTTP1.1 ALPN and absent ALPN are accepted, both through the same strict H1 parser; other negotiated protocols/h2c/upgrade/HTTP2 prior knowledge refuse. One owning task serializes each connection; no Hyper/detached driver/split writer. It supports repeated requests on one TLS connection, not a handshake per request. At most128 owned connections and128 active requests, idle30s, connection lifetime300s,4096 requests/connection; server drain5s then shared runtime aborts/owns tasks. Listener generation retires on shutdown, error and cancellation (RAII), before normal drain. These bounds are transport limits, not authorization TTL/grace.

Exactly POST `/v1/kubernetes/subjectaccessreviews`, HTTP1.1, exact configured Host. Headers16KiB/64fields, strict CRLF and mature httparse with additional framing constraints. Exactly one canonical decimal Content-Length1..32768, supported application/json (optional literal charset=utf-8), one Authorization. Any TE, Expect/100-continue, trailer, upgrade, content-encoding, duplicate framing/auth/Host fields, noncanonical/comma length, unsupported Connection nominations or absolute/query target refuses/closes. No chunked body support. Body authentication/admission precede JSON decoding. Fixed safe errors have no input echo; ambiguous framing/timeout/EOF may close without an HTTP response. Decoder malformed JSON/duplicates/size/depth/envelope =>400; valid unsupported/unknown/source-withdrawn/native-denied input =>HTTP200 explicit deniedtrue, never no-opinion. Failures/non200/transport outage require API-server failurePolicyDeny.

The driver reads only the needed header/body frame and does not evaluate another request before previous response completion. Rustls can buffer later plaintext from one TLS record, so this is not a claim to detect/reject every client pipeline. Any queued next request is processed strictly AFTER full previous flush with new credential/admission/deadline/View. Connection reuse cannot renew prior source or allowing owner. Header currently reads bytewise to avoid read-ahead ambiguity; this is an acknowledged optimization area, not extreme-throughput qualification.

## Native original time and final send boundary

A request has an original1s native BOOTTIME budget. Successful first-byte poll captures stamp BEFORE polling TLS; Pending does not admit an application byte or allocate request Arc. Successful stamp is retained across auth/body/decoder/evaluation/serialization/write. Idle wait has its own original BOOTTIME bound; no timestamp reset after awaited first byte, no hidden grace/foreign absolute comparison. Tokio timeouts assist cancellation but BOOTTIME checks govern admission/emission. Clock read failure/reversal/expiry irreversibly retires that budget. Native static source_remaining's conventional1000ms is NOT treated as source evidence; K8s-owned views use their original actual source_lifetime/readiness, never renewed by sampling or socket reuse.

Private authorizer captures one Arc<View>, maps principal+route and evaluates existing grants on it, checks health/source/budget, constructs private capture then rechecks after all callbacks. Fixed HTTP response header allocation completes before installing owner/final current checks. Current checks finish clock dependencies before healthy/current-Arc observations. Same-number View replacement retires old capture. No store/SQL/network callback/publication mutex in the hot evaluation/current path.

A private guard wraps raw TCP BELOW rustls. Every scalar/vectored write, flush and shutdown observes connection/listener/original operation/source/current owner; listener-active is checked AGAIN after clock dependencies. A failed gate/IO/capture cannot revive. Retain same owner while TLS accepts plaintext and encrypted writes are Pending. Only after entire response write_all PLUS successful TLS.flush, !is_handshaking, !wants_write and final current check may owner be cleared for next request. No await/read/callback between final observation and synchronous state reset. Read-error alert writes and shutdown pass same raw guard. Failure/cancellation drops the connection; it never switches to a permissive next owner to flush old Allow bytes. No detached writer remains. Config/token/header/body owned buffers use zeroization where applicable; this does not erase every TLS/parser/kernel temporary copy.

This is per-poll send-boundary observation, NOT an atomic distributed revocation lease, remote receive/ACK guarantee or recall of already kernel-accepted bytes. Already complete responses/operations/streams cannot be retracted; API-server may receive accepted bytes later. No blanket final Kubernetes-effect guarantee.
