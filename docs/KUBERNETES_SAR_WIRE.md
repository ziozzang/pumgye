# Private SAR wire decoder

Private binary module `sar_wire` is now consumed by the explicit default-off listener described in [KUBERNETES_SAR_SERVER.md](KUBERNETES_SAR_SERVER.md). The decoder itself has no listener or authentication. No public API, caller authentication, listener, cluster selection, authorization capability, source lifetime or final transport guarantee is added. No pooling/keepalive/H2 policy is selected. The next adapter must authenticate a fixed API-server peer before body decoding, acquire bounded admission, evaluate mapping+grants on one captured current View, and preserve original time/current/source fences through the reviewed response boundary.

Decoder input is at most32768 bytes, including whitespace. One duplicate-sensitive JSON visitor allocates only after byte bounding and refuses nested containers at depth17 (root is1), before allocating the excessive container. It rejects duplicate decoded object keys everywhere, including escape aliases in ignored/unsupported fields, and trailing JSON/non-UTF8/syntax errors. Parsing directly to ordinary Value first would lose those duplicate keys and is deliberately avoided. Errors contain no input text; caller receives only private BadRequest (futureHTTP400).

Exact apiVersion authorization.k8s.io/v1, kind SubjectAccessReview, and object spec are required; malformed/wrong/missing envelope returns BadRequest. Structurally valid envelope with unknown fields, unsupported security/conditional attributes, bad identity fields, both/neither attrs, or unsupported resource/path scope returns explicit Decoded::Deny. This is not no-opinion. Supported only carries untrusted existing core Principal/Attributes metadata; it authenticates and permits nothing.

Metadata absent/{} /creationTimestamp:null and status absent/{} /allowed:false are accepted only as inert generated-object defaults. All other metadata/status fields/shapes refuse. Input status can never authorize or be echoed. Missing groups/extra means empty; missing UID means absent, explicit null/empty UID refuses. Core group/subresource omission maps to their standard empty values. No guessed namespace/name/version or synthetic IP/Sum/AAL. Fields/values follow current bounded core constraints: user/UID/group/extra1..256 bytes excluding controls; groups64, extras32x8; duplicate group/extra values refuse; anonymous/system:unauthenticated refuse.

Only named namespaced resource get/update/patch/delete, subresource empty/status/scale; no selectors, wildcard, create/list/watch/cluster-scoped/proxy/exec/connect/escalation. Nonresource has exact bounded ASCII path/lowercase verb with no percent/query/double-slash/dot segments/normalization. Existing core independently validates inputs again during future native evaluation; no core API/semantics changed.

Fixed private Allow/Deny JSON byte constants contain only apiVersion/kind/status, consistent allowed/denied flags and fixed reason. No user/spec/extra/status/header reflection or dynamic reason allocation. Only the private listener can select Allow after captured native authorization and final owner checks; no public grant constructor exists. Inline Decoded (~264bytes) deliberately avoids an extra request Box allocation; only its large-enum lint is narrowly allowed. Throughput remains unmeasured.

Fixture `tests/fixtures/sar-v1-generated-shape.json` uses reserved synthetic identity and shape derived from public upstream Kubernetes v1 Go tags. Its adjacent provenance explicitly states it is NOT an actual API-server capture or executed Go serialization. Actual API-server envelope/HTTP integration is a later independent gate; old v1beta1 webhook sample fields are not treated as v1 contract. Native mapping test confirms Supported conversion reaches the same core grants and grant deletion denies; it does not authenticate caller or exercise network transport.
