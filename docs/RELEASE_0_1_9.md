## Publication, adoption and remaining limits

Local release assets are independently signed and checked before publication; signing alone does not deploy or enable SAR. Existing0.1.8 published assets are immutable. Public release and operating configuration changes remain separate actions. Enable SAR only with explicit fixed-cluster/caller configuration and reviewed API-server authorizer ordering; do not change an existing master from this document.

Actual v1 interoperability does not mean a raw request-envelope capture or observed production webhook connection reuse was obtained; persistent-H1 reuse is directly proven by local mTLS fixtures. The actual API-server gate covers named GET/PATCH, not every Kubernetes verb, admission, CNI or full Kubernetes policy semantics. Actual native Kubernetes policy-source authority and the SAR adapter remain distinct owners. Source lease expiry has native capture tests, not a new actual socket/source-expiry claim. Raw send-boundary checks cannot recall kernel-accepted responses or already admitted operations/streams. H2 per-stream ownership, extreme throughput and distributed source/cache qualification remain pending. Unsupported native clock refuses opt-in SAR without weakening legacy paths.
