# Native Human observed permits — integration candidate

This additive implementation is not a published or operating Human authorization claim. Actual Hop Human source/RPC/SDK qualification and the exact source-scope fingerprint pin are required before final acceptance. Service and Workload defaults and RPCs remain unchanged. Human projection contract4 and Root final enforcement are a following stage.

Build with the existing `observed-authentication` feature. Activate only with `--human-observed-permits --human-authentication-live human-live.json` plus existing `--authentication-trust`, `--permit-key`, `--network-live`, `--route-live`, `--projection-live` and mandatory mTLS gRPC listener resources. Without this explicit Human activation, the Human permit service is not mounted. No application header selects this class. No insecure TLS/plaintext/legacy authentication fallback exists.

`human-live.json` is a bounded administrator-owned document with `transport` (the existing issuer_ref/address/server_name/ca/certificate/key/token_env/observed_clock_rates fields), explicit `minimum_source_revision`, `minimum_application_generation`, `minimum_key_registry_revision`, and `scopes`. Each scope contains service, audience, app_id, route_id, route_revision, destination_sha256 (32 JSON bytes), header_policy_revision, header_names and reserved_names. TLS resources and caller secrets are resolved from fixed configuration references, never request fields. Source/app/key floors concern publication ownership, not global user/session revisions. Human users with different legitimate authz revisions must remain independent.

The fixed PEP computes H1 v2 from actual final body/header/route bytes through the public SDK preparation API. Pum receives existing AuthenticatedResourceRequest context/proof/digest and route reference. Pum independently calls Hop ObserveTime through a persistent, fixed-peer Human SDK client. Only opaque SDK Observation creates its private Human evidence. Context, IP, subject, AAL and digest DTOs by themselves grant nothing. Pum does not manufacture a body, reexecute transforms or construct identity from a caller assertion. The mandatory source report fingerprint is validated by the public SDK. Pum compares the opaque Observation::scope() route, revision and destination with its actual route owner; it never substitutes another configured scope with the same service/audience or a global source revision.

HumanObservedProjectionPermits Issue and Observe use the owning Authority's exact compiled View, shared `human_users`, actual Sum network evidence, route owner and plan owner. Actual authenticated AAL1/2 is supplied to both plan and policy. AAL0/3, API-context Human grants, cross-class map fallback and metadata-based TOTP elevation are refused. Assignment role/network/resource requirements remain unchanged; required AAL3 remains denied. Policy publication uses the existing Document CAS/database, not a new identity or grant store.

The Human transport captures original BOOTTIME admission plus exact policy/authentication generation before caller callbacks and protobuf decode. A private one-shot extension carries that admission; the handler cannot reconstruct it from a header or fall back to sampling later. Owner replacement, caller loss, source observe miss/restart, grant withdrawal and expired original age refuse. Independent ObserveTime and consuming refresh do not extend original authentication evidence. Publication evidence is point-in-time and is not a distributed revocation lease or complete asynchronous snapshot engine.

Signed permit full lifetime and prerequisite-shortened admission budgets remain distinct. Reports use Pum's own pobs1 source clock, exact proof hash and TTL0. Foreign source ticks are never compared to UTC or directly minimized with another clock. Final origin emission and atomic paired replay are not performed by Pum Issue/Observe. Contract4 must use the same canonical nonce namespace/transaction as all existing classes and modes in Hop; this candidate creates no new replay ledger.

Tests of pure wire signatures or DTO refusal are structural tests only. Final qualification requires real native OIDC/LDAP primary plus real TOTP -> actual Hop RPC -> opaque SDK independent observation -> typed Pum permit, including revoke/ABA/cancel/restart/expiry and owner changes around signing. A four-core backend0/1 and cross-contract replay gate follows in Root/Hop integration. No throughput or 100k qualification is claimed.

`HumanResourceAuthorization.Decide(ResourceDecisionRequest)` is also mounted only under the explicit Human activation. It evaluates fixed-PEP Human subject/AAL1-or2 metadata against the same current Authority View and returns TTL0. It does not call Hop or produce authentication, a signed permit, a freshness lease, or any final credential. An apparent preliminary Allow cannot bypass independent Human ObserveTime and final permit requirements. The real-binary fixture checks no Source RPC occurs during this preliminary query, malformed/unknown identities and invalid AAL refuse, grant deletion never falls back to legacy users, and default startup leaves both Human services unmounted.

The explicit external runtime test is `human_native_runtime::actual_native_hop_sdk_to_pum_authority_human_permit` in `tests/human_observed_permit.rs`. It is ignored in ordinary workspace runs because it requires a separately provisioned native portal driver and exact compiled Hop binary. Invoke it with `--ignored --exact`, `OWNED_HUMAN_RUNTIME_FIXTURE`, `OWNED_HOPAE_BINARY`, and fixed `OWNED_HUMAN_PROVIDER=oidc|ldap`; `OWNED_HUMAN_LDAP_STARTTLS=1` selects mandatory StartTLS instead of LDAPS. Missing prerequisites fail explicitly; no metadata-signed peer substitutes for Hop. It keeps private evidence directories, uses actual-body SDK preparation, checks live original proof budget after native logout, and exercises Pum's actual binary/SQLite policy CAS. Its Sum/route/plan peers are protocol fixtures, so it does not establish an actual four-core/H4/Root chain or all-provider Human MFA support.
