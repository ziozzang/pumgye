# 인증 receipt 검증 (미릴리스)

[English](AUTHENTICATION_RECEIPTS.md)

소유자 서버 라이브러리 `pumgye_server::authentication`은 고정한 공급자 독립
호패 receipt 계약을 사용합니다. `pumgye-core`에는 공급자·세션·HTTP·DB 의존성을
추가하지 않습니다.

`ServiceTrust`는 서버 소유 발급자/키 세대/공개 키·신원 원천 epoch 기반값·서비스/
대상·최소 프로필 리비전으로 구성합니다. 요청 메타데이터가 다른 신뢰 키나 등급을
선택할 수 없습니다. 정규 Service/AAL0 신원·프로필/자격 세대 일치·정규 서비스
epoch·최종 요청 digest·Authentication 목적의 서명/시간 경계를 검증한 뒤에만
`CheckedService`에 검증 문맥·정확한 receipt hash·만료를 보관합니다. 공개 생성자·
Clone·Debug·직렬화가 없고 입력의 숫자 문맥을 나중에 바꿔도 검증 사실은 바뀌지
않습니다.

정상 추출·유효하게 서명됐지만 잘못된 범위/종류/세대·신원/프로필 epoch 불일치·
최소 리비전·잘못된 키/목적·모든 byte 변조·시간 경계를 검사합니다. 불변 자원을
사용하며 요청 중 SQL이나 공급자 호출은 없습니다.

암호학적 서버 라이브러리 경계이며 활성 permit endpoint는 아닙니다. 정적 리비전
하한이 실시간 호패/키 신선도를 보장하지 않습니다. 서명기는 현재 신원/키/epoch
경계·검증된 네트워크 근거·네이티브 자원 Allow·최종 요청/계획 바인딩을 결합하고
후보를 공개하기 전에 각 소유자를 다시 확인해야 합니다. 자격 변환에서는 재사용
소비 경계도 필요합니다. 서버 신뢰 설정 로딩/게시·영속 회수 하한·RPC 연결은 남아
있습니다. 기존 서비스/자원 전송은 유지합니다.

## 검증 신원의 자원 경계 (미릴리스)

`authorization::authorize_resource_then`은 `CheckedService`의 서비스·정규 신원·
AAL만 평가합니다. 네이티브 자원 요청에 신원·서비스·인증 수준·등급을 덮어쓰는
필드는 없으며 컴파일한 카탈로그에서 등급/행위 권한을 정합니다. 필수 소유자 경계와
시계 콜백으로 진입·후보 생성·최종 반환을 보호합니다. 인증 검증 시각은 시간 역행
하한이고 인증/네트워크 만료와 시각 역행은 후보를 거부합니다. 콜백은 소유자
메타데이터를 받고 성공까지 결과를 비공개로 보관해야 합니다.

실제 서명 인증 receipt와 네이티브 자원 Allow를 결합하고 네트워크/행위 거부·
최초 회수/만료·후보 생성 중 회수·작업 뒤 인증/네트워크 만료와 시각 역행을
검사합니다. 공개 서버 라이브러리 어댑터이며 RPC 연결은 아직 없습니다. 현재
소유자 콜백은 실제 신원/키/네트워크/정책/라우트/계획 원천에서 제공해야 하며
이 helper 자체가 원격 신선도를 조회하거나 서명 permit을 제공하지 않습니다.

## 네이티브 permit 후보 서명기 (미릴리스)

`permit::Signer`는 독립 품계 서명 신원과 Permit 목적을 사용합니다. 검증 신원의
자원 판정 안에서 실행하고 결과 `SignedPermit` 반환 전에 네이티브 소유자와
관측한 시각을 다시 확인합니다. 정확한 인증 receipt hash·검증 신원/서비스/대상/
요청·판정/자원/행위·원천 epoch·정책/카탈로그/네트워크/라우트/계획 리비전을
바인딩합니다. 카탈로그/정책은 하나의 원자적 문서 리비전을 공유하며 호출자
등급/인증 수준을 받지 않습니다. nonce는 OS CSPRNG에서 생성합니다.

인증·네트워크·정책·라우트·계획·1초 제한 중 가장 이른 시각에 만료합니다. 독립
수신 검증으로 목적/키 분리·정확한 체인/리비전·만료·서로 다른 nonce를 확인하고
거부·최초/최종 소유자 회수·잘못된 리비전·만료 계획·시각 역행은 후보를 폐기합니다.
workspace 44개 검사와 엄격한 Clippy가 통과했습니다.

서버 라이브러리 기능이며 설정된 권한 endpoint는 아닙니다. 네이티브 원천 상태와
필수 신선도 콜백은 실제 소유자에서 제공해야 합니다. 서명 키 로딩/회전·원천 발견/
일관성·RPC 연결·수신 재사용 소비·자격 변환은 계속 필요합니다. 이 소스 변경으로
운영 permit 발급기를 활성화하지 않습니다.

## 네이티브 permit 서명 자원 (미릴리스)

`--permit-key <file>`로 `issuer_ref`·`key_epoch`·`public_key`(base64 Ed25519 공개
bytes)·`seed_env`(환경변수 참조)의 JSON을 선택적으로 로딩합니다. inline `seed`를
포함한 알 수 없는 필드는 거부하고 파일 크기는 16 KiB로 제한합니다. 공개 신원/
세대/참조 문법을 검사한 뒤에만 비밀 자원을 조회합니다. 32-byte seed와 선언한
비취약 공개 키가 일치해야 하며 인코딩된 seed·디코딩/파일 버퍼를 zeroize합니다.
누락/잘못된 자원은 DB 생성·리스너 바인딩 전에 실패합니다. 관리자 상태에는
`permit_key_configured`만 표시합니다.

릴리즈 자산·호패 인증 신원과 별도의 배포 permit 신원을 사용합니다. 현재 로딩
경계는 재시작이며 영속 키 이력은 아래 시작 경계로 보호합니다. 동적 게시는 남아 있습니다. 키 로딩이
permit RPC를 활성화하거나 실제 소유자/네트워크/계획 검사를 충족하지는 않습니다.
조회/관측 전용 모드와 이 옵션을 함께 사용할 수 없습니다. 옵션이 없는 기존
배포는 일반 판정 동작을 유지합니다.

## 서버 소유 인증 신뢰 로딩 (미릴리스)

`--authentication-trust <file>`은 최대 64 KiB·1..128개 `entries` 문서를 로딩합니다.
항목은 `issuer_ref`·`key_epoch`·`identity_epoch`·`service`·`audience`·
`minimum_revision`·base64 `public_key`를 선언하며 알 수 없는 필드와 비밀 필드는
거부합니다. 네이티브 검증으로 참조·세대·리비전 하한·비취약 공개 키를 확인하고
중복 발급자/서비스/대상, 같은 발급자의 키/세대/신원 기반 불일치와 발급자 사이
공개 자원 재사용을 거부합니다. 같은 발급자/서비스의 여러 대상은 하나의 활성
신원을 공유할 수 있습니다.

컴파일된 신뢰는 참조를 사용하는 발급자/서비스/대상 해시 조회로 요청 중 복합 키
문자열을 할당하지 않습니다. 요청이 공개 키를 선택하거나 미선언 범위를 추가할 수
없습니다. 잘못된 신뢰는 DB 생성/리스너 바인딩 전에 거부하고 관리자 상태에는
`authentication_trust_entries`만 표시합니다. 조회/관측 전용 모드와 함께 설정할
수 없습니다. 로딩은 재시작 경계이며 실시간 호패 재검증·동적 신뢰 게시·permit RPC 활성화는 아직 구현하지 않습니다.
키 회수는 아래 영속 시작 경계로 보호합니다.

## 영속 시작 키 이력 (미릴리스)

리스너를 열기 전에 인증·permit 공개 키의 통합 레지스트리와 SHA-256 감사를
자체 SQLite DB에 원자적으로 저장합니다. 통합 활성 키는 64개, 발급자/용도
하한은 128개, 과거 공개 키는 256개로 제한하며 신뢰 범위 128개 제한은 별도입니다.
이 경계를 위한 요청 중 DB 조회는 없습니다.

성공한 시작 전환마다 레지스트리 리비전이 증가합니다. 설정 제거 시 키를 회수하고
이력을 보존합니다. 동일한 활성 키는 유지할 수 있지만 교체에는 높은 epoch와 새
공개 키가 필요합니다. 회수·교체된 키는 어떤 epoch에서도 재사용하거나 다른 발급자/
용도로 이동할 수 없습니다. 전환 실패 시 스냅샷·감사를 유지하고 시작을 거부합니다.
실제 프로세스 시작·DB 재시작·회수·새 키 교체·쓰기 실패를 검사합니다.

서비스 프로필 최소 리비전·신원 epoch의 영속화, 실시간 프로바이더/앱 신선도,
전체 DB 백업 롤백 방지와 permit RPC 활성화는 이 변경에 포함되지 않습니다.
분산 하한과 복구 보호는 추가 구현이 필요합니다.
