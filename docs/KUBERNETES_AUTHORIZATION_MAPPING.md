# Kubernetes API mapping core prerequisite

This stage adds optional `Policy.kubernetes_authorization` version 1 metadata to the same `Policy.compile()` / immutable `CompiledPolicy` as existing grants. It adds no listener, authenticated caller, Human/Workload proof, receipt, source lease, database/cache, or Kubernetes deployment. Absent or null metadata is omitted during serialization; existing policy defaults remain unchanged. The caller must authenticate an API-server peer and supply its fixed cluster separately, capture one current authority View, and fence source lifetime/publication/deadline through response emission. An old compiled snapshot remains immutable and can still Allow; this pure module cannot retire it.

Metadata consists of `principals` and `routes` (each at most 4096). A principal has `cluster`, exact `user`, `uid:{mode:"absent"}` or `uid:{mode:"exact",value:"..."}`, `required_groups`, `required_extra`, and `subject`. Cluster is 1..64 ASCII letters/digits/underscore/hyphen, with no colon. Subject must be a nonempty label in the exact `k8sapi:<cluster>:` namespace. This is a native assignment label, not an authenticated principal or numeric capability. No username-prefix/group-only inference or Service/Workload fallback occurs.

Groups are required-set constraints: additional bounded groups cannot select additional rights. Each required extra key must have exactly the configured value set, independent of order; additional bounded extra keys are inert. UID absence differs from any exact UID. Exactly one principal must match, even when overlapping matches name the same native subject; ambiguity refuses. Duplicate group/extra values, extra keys, and exact configuration bindings refuse. Anonymous or `system:unauthenticated` assertions refuse. User/UID/group/extra text is nonempty, at most 256 bytes, and excludes controls. Request/config groups are capped at 64, extra keys at 32 and values per key at 8; per-(cluster,user) candidates are capped at 64.

Routes select exact attributes and existing native `service`, catalog `resource`, and `action`. Duplicate (cluster, attributes) routes refuse compilation. Targets must exist and use explicit `kubernetes_api` authorization context; the existing users/roles/permissions/class/minimum-AAL rules remain the only grants. Effective AAL is always zero; no fake IP, Sum evidence or assurance is supplied. Grant deletion, class change or AAL requirement changes alter results in the same recompilation.

Resource attributes use `kind:"resource"` and all explicit `group`, `version`, `resource`, `subresource`, `namespace`, `name`, `verb` strings. Empty group means core API; it is not a wildcard. Only named namespaced get/update/patch/delete are supported. Subresource is empty, status or scale. Wildcards, empty namespace/name, create/list/watch, cluster-scoped operations, escalation verbs, proxy/exec/connect and unsupported subresources refuse. Nonresource uses `kind:"non_resource"`, exact `path` and lowercase HTTP `verb`; paths contain only ASCII letters/digits and `/_.-`, start with slash, and exclude double-slash and dot segments. Percent escapes/query/prefix/glob matching or normalization are unsupported. Unknown fields including selectors refuse decoding. This deliberately limited prerequisite is not full SAR wire/API compatibility.

`evaluate_kubernetes_request(fixed_cluster, principal, attributes)` returns only an explicit mapping denial or existing native `ResourceDecision`. Constructing its metadata input authenticates nothing. Transport/body admission, duplicate top-level SAR wire checks, caller mTLS, overload, response serialization, source withdrawal/current View fences, API-server failure policy and authorized cache disabling remain future adapter gates. Existing open API operations/streams cannot be recalled by this decision boundary. No throughput claim is made.
